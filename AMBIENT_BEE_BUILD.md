# Ambient Bee v3 — Working Build

## What is actually working

This document records the tested state of Ambient Bee on 21 September 2026. It intentionally describes the working system rather than an idealized architecture.

### Proven pipeline

Samsung Voice Recorder
→ FFmpeg
→ native whisper.cpp HTTP server
→ Xkira Mistral API
→ SQLite
→ Obsidian-compatible Markdown vault
→ rclone Google Drive

### Tested components

- Samsung Voice Recorder audio ingestion works.
- The working recording location is `/storage/emulated/0/Recordings/Voice Recorder`.
- The pipeline was narrowed to that directory so ordinary Call recordings are not ingested.
- FFmpeg converts source audio to 16 kHz mono PCM WAV.
- Native whisper.cpp runs on `127.0.0.1:8080`.
- Whisper model: `ggml-tiny.en.bin`.
- Whisper produces the transcript.
- Mistral via Xkira produces the structured memory extraction.
- Model: `mistralai/mistral-large-2512`.
- Endpoint: `https://api.xkiro.com/v1/chat/completions`.
- SQLite stores recordings, memories, todos, people and run statistics.
- Daily Markdown logs are rebuilt under `vault/Daily/`.
- TTS through Termux works.
- rclone sync to `gdrive:AmbientBee` works.
- The tested 6.7 MB recording completed the entire pipeline successfully.

## Division of labour

**Whisper.cpp**

Speech recognition only. It converts the recording into the transcript.

**Mistral**

Memory extraction. It turns the transcript into:

- summary
- todos
- people
- follow-ups
- decisions
- tags

Therefore the prose shown above the transcript in a Daily log is generated by Mistral, while the transcript itself comes from Whisper.

## Daily memory format

A Daily log contains:

1. timestamp and source recording
2. Mistral summary
3. Decisions
4. Todos
5. Follow-ups
6. full/available Whisper transcript

This is already the daily reasoning substrate. A separate chatbot is not required for ingestion.

## Proper local app

`bee_web.py` is the local control-room UI around the existing engine.

Run:

```bash
python ~/bee_web.py
```

Then open:

```
http://127.0.0.1:8787
```

The UI provides:

- Bee run control
- recording statistics
- latest memory
- open todo list
- todo completion
- memory search
- Daily log viewer
- morning brief

The web server binds to localhost only. It does not publish the memory vault to the public Internet.

## Important deployment note

Do **not** commit a live API key to GitHub. The working phone installation may use its local hardcoded key if desired, but the repository version should remain secret-free.

The local Samsung Voice Recorder directory change is also a phone-side configuration change. If `ambient_bee.py` is copied fresh from GitHub, reapply that local recording-directory change.

## Commands

Existing engine:

```bash
python ~/ambient_bee.py --setup
python ~/ambient_bee.py --run-once
python ~/ambient_bee.py --watch
python ~/ambient_bee.py --ask "..."
python ~/ambient_bee.py --brief
python ~/ambient_bee.py --digest
python ~/ambient_bee.py --todos
python ~/ambient_bee.py --done 12
python ~/ambient_bee.py --stats
```

Local app:

```bash
python ~/bee_web.py
```

## Design principle

Ambient Bee is not primarily a chatbot.

The core loop is:

**capture → transcribe → extract → remember → organize → retrieve**

The conversational `--ask` interface is optional. The memory system remains useful without it.
